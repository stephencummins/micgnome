first, the way back

If the mic will not start. connect it to a computer and hold the white + grey buttons during startup to get the disk back, then fix or delete config.json.

Mind your ears. The socket is a stereo line output — 8 dBu, 2 VRMS max, 98 dBA SNR. Designed for a K.O. II or an audio mixer, not for headphones directly — at 2 VRMS it can be very loud.

Every block, range and rule the EP–2350 understands, on paper, because a web page is no help with the lid off and a text editor open. Generated from the same source Mic Gnome validates against, so it cannot quietly disagree with the tool.

the shape of the file

{
  "name": "MY PACK",
  "comment": "yours to modify and pass on",
  "presets": [
    {
      "pos": 0,
      "name": "PRESET ONE",
      "comment": "what it is for",
      "list": [
        { "effect": "DIST", "amount": 10.0 },
        { "effect": "SAMPLE" },
        { "effect": "REVERB", "time": 0.4 }
      ],
      "handle":  { "row": 0, "param": "amount", "depth": 20.0 },
      "shake":   { "row": 2, "param": "time",   "depth": 0.5 },
      "trigger": { "row": 1 }
    }
  ]
}

Four presets go in presets, one per slot on the orange button. Inside each, list is the chain, top to bottom. The three lines under it are the only things that move: the handle you squeeze, the shake of the mic, and the sample button. Each names a row — a position in that list, counting from zero.

the three buttons

orangesteps through no effect and the four preset slots — the first position is your voice, dry
whiteselects which of the four sample slots is armed
greyplays the selected sample

The four sounds already in it are horn, applause, ringside bell, censor beep — the beep mutes the mic while it plays, which is the point of it. A pack needs no wav of your own unless you want one.

modulation

handlethe squeeze. one per preset. { "row": n, "param": "x", "depth": d }
shakethe gyroscope. keeps moving after you let go.
lfothe only motion that runs on its own. shapes: sine, square, sawtooth, random. also takes speed, mpy, phase.
triggerthe sample button. point it at the SAMPLE row, counting from 0.
target: "lfo"on the handle, squeezes the lfo itself rather than an effect.

the rules that bite

  • rows count from 0. The second row is row 1. Every row in a modulation block, and the one in trigger, is an index into list.
  • audio falls top to bottom. A block only works on what is above it. Put SAMPLE last and the built-in sounds play dry; put it earlier and everything below it processes them too.
  • no trigger, no sample. It has to name the SAMPLE row itself. Pointed at an effect row instead, it is reported to switch that effect in and out while held — and the sample button stops working.
  • effect names are UPPERCASE. Parameters are lowercase and hyphenated: wet-level, cross-feed, lowpass-cutoff.
  • use once per chain: DELAY, HARMONY, REVERB, SSB.
  • BUS is 1 or 2. A bus row is a copy of whatever is at that point — dry included, unless the block's own dry-level says otherwise. SAMPLE on BUS 2 is reported silent; put it on BUS 1.
  • a wav the config never names does not play. Every file needs an entry under samples, with a playmode: oneshot, hold, startstop.
  • check your braces, quotes and commas. A broken file is a mic that will not boot — see the recovery note.

where the guide says nothing

  • how a BUS sums — The guide describes BUS in a single line and does not define how buses are summed.
  • what a sample file may be called — The guide names the sample files 1.wav to 4.wav and never says whether the firmware will read any other name. If it will not, a pack built from files with their own names is silent and gives no reason why.
  • SAMPLE inside a bus — The guide is silent on SAMPLE inside a bus; a player reports SAMPLE on BUS 2 gives no playback, and puts it on BUS 1 instead.
  • trigger on an effect row — The guide only ever points "trigger" at a SAMPLE row. A player reports it works on an effect row too, switching that effect in and out while held, and that the sample button stops working when you do. The author of the config could not reproduce it.
  • whether a trigger is required — The guide does not say whether "trigger" is required when a preset contains a SAMPLE row; a player reports that without one, pointed at the exact SAMPLE row, nothing plays.
  • capitalisation of parameters — The guide requires uppercase effect names but shows parameters in lowercase; it never states whether parameter names are case-sensitive.
  • keys the guide never mentions — The guide does not say whether the firmware ignores unrecognised keys or refuses the file.

who told us the rest

Not from Teenage Engineering. People with the mic in front of them, which is weaker than the guide and stronger than nothing — enough to warn you, never enough to stop you. Anything in this book marked not in the guide is waiting to be confirmed on hardware.

  • windowbed’s example pack — A four-preset config walked through running on a real EP-2350 TING — the mic bundled with the EP-40 RIDDIM. Same model number as the standalone unit; the two differ in labelling and in the presets they ship with (the TING is sold on echo, echo + spring, pixie and robot), which are built from these same blocks. Whether they differ in any other way is not known, so everything sourced here stays a warning until it has been heard on a standalone mic. https://www.youtube.com/watch?v=C2KM5qBMkKw, 2026-09
  • the replies under it — Replies under that video, from other TING owners. Three claims worth having: a "trigger" pointed at an effect row switches it in and out while held (and kills the sample button); on newer firmware your own wavs need an explicit "samples" block listing every one; and SAMPLE only ever moves the sample, never the voice. https://www.youtube.com/watch?v=C2KM5qBMkKw, 2026-09
